## Jawaban Tugas Pendahuluan
Kode awal berfungsi dengan baik, tetapi masih melanggar beberapa prinsip Clean Code:

1. Fungsi `fetchOrderDetails()` memiliki terlalu banyak tanggung jawab, yaitu mengambil data dari API, menampilkan modal, mengatur tombol tutup, dan mengatur tombol konfirmasi.
2. Penggunaan Promise chaining (`.then()`) membuat kode lebih sulit dibaca ketika logika semakin kompleks.
3. Nama beberapa variabel masih kurang deskriptif, seperti `token`, `modal`, dan `detailsDiv`.
4. Event listener dapat ditambahkan berulang kali setiap kali fungsi dipanggil sehingga berpotensi menimbulkan bug.
5. Kode tampilan dan logika bisnis bercampur dalam satu fungsi.

## Refaktorisasi yang Dilakukan

### 1. Memisahkan Tanggung Jawab Fungsi

Kode dipecah menjadi beberapa fungsi yang masing-masing memiliki satu tugas:

- `fetchOrderDetails()` mengatur alur utama.
- `getOrderDetails()` mengambil data dari API.
- `showOrderModal()` menampilkan modal.
- `renderOrderDetails()` menampilkan informasi pesanan.
- `setupConfirmButton()` mengatur perilaku tombol konfirmasi.

### 2. Menggunakan Async/Await

Promise chaining diganti dengan `async/await` agar alur program lebih mudah dibaca dan dipahami.

### 3. Menggunakan Nama Variabel yang Jelas

Beberapa nama variabel diperbaiki agar lebih deskriptif:

| Sebelum | Sesudah |
|----------|----------|
| token | authToken |
| modal | orderModal |
| detailsDiv | orderDetailsContainer |
| closeBtn | closeButton |
| confirmBtn | confirmButton |

### 4. Mengurangi Komentar yang Tidak Perlu

Komentar hanya digunakan untuk menjelaskan aturan bisnis yang tidak langsung terlihat dari kode, sedangkan bagian yang sudah jelas dijelaskan melalui nama fungsi dan variabel.

## Kesimpulan

Hasil refaktorisasi membuat kode lebih mudah dibaca, dipelihara, dan dikembangkan. Setiap fungsi memiliki tanggung jawab yang jelas, nama variabel lebih bermakna, serta struktur kode menjadi lebih sesuai dengan prinsip Clean Code dan Single Responsibility Principle (SRP).
