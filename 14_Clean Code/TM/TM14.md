## Soal
Dari dua kode di bawah ini, mana yang kamu ingin cari masalahnya dan perbaiki di tengah-tengah malam, katakanlah jam 1 malam? Mengapa?

```javascript
function processUser(user) {
  if (user) {
    if (user.isActive) {
      if (user.hasPermission) {
        return doSomething(user)
      }
    }
  }
  return null
}
```
```javascript
function processUser(user) {
  if (!isValidCandidate(user)) return null;
  return doSomething(user);
}

function isValidCandidate(user) {
  return user && user.isActive && user.hasPermission;
}
```

## Jawaban
Saya akan memilih kode kedua untuk diperbaiki atau dianalisis pada jam 1 malam.

```javascript
function processUser(user) {
  if (!isValidCandidate(user)) return null;
  return doSomething(user);
}

function isValidCandidate(user) {
  return user && user.isActive && user.hasPermission;
}
```
Alasannya karena kode kedua lebih mudah dibaca dan dipahami. Logika validasi dipisahkan ke dalam fungsi isValidCandidate(), sehingga fungsi processUser() hanya berfokus pada satu tugas, yaitu memproses pengguna yang valid.

Sebaliknya, kode pertama menggunakan nested if yang membuat alur logika lebih sulit diikuti.

Ketika terjadi bug atau perlu dilakukan perubahan, saya harus menelusuri beberapa tingkat kondisi terlebih dahulu. Pada kondisi lelah atau saat debugging di tengah malam, struktur seperti ini lebih rentan menyebabkan kesalahan dan membutuhkan waktu lebih lama untuk dipahami.

Selain lebih mudah dibaca, kode kedua juga lebih mudah dipelihara. Jika di kemudian hari ada syarat baru, misalnya pengguna harus memiliki email yang terverifikasi, perubahan cukup dilakukan pada fungsi isValidCandidate() tanpa mengubah logika utama processUser().

Kesimpulannya, saya lebih memilih kode kedua karena lebih ringkas, mudah dibaca, mudah diuji, dan lebih mudah dipelihara sesuai prinsip Clean Code.
